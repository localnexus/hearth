# 2.5 Control panel & live status (`:65000`)

*What this covers: the browser control panel served while the loop is up — driving turns without speaking, mute/PTT, the live token/context status block, and its loopback-only default.* · Runbook index: [`README.md`](README.md)

When the loop is up it also serves a **control panel** at `http://<host>:65000/` (startup log prints `[control] web box → …`; port overridable with the `WEB_PORT` env var). Open it in a browser on the same machine. It lets you **drive turns without speaking** — built for quiet/shared rooms and long soak sessions.

**Controls:**
- **Text turn** — type + Enter (or Send). Injected as a user turn (bypasses mic/STT); if the bot is mid-reply it interrupts (text barge-in). Nothing registers until you submit, so you can edit freely first.
- **Mute mic** — latched toggle. Mutes the mic *before VAD* so a muted mic can't trigger barge-in or a half-open turn; the process keeps running and **text still works while muted**. Spoken input resumes on Unmute.
- **PTT (hold)** — momentary override: hold the button (or hold **M** while the page is focused) to open the mic, release to return to the latched baseline. Works from either baseline.
- **`MIC:` indicator** — always shows `LIVE (baseline)` / `MUTED (baseline)` / `OPEN (PTT held)`. The Mute toggle *is* the baseline; PTT is a temporary override.
- **Record** — capture the session to disk (M7). Always records the companion's voice (TTS); tick **my mic** and/or **background music** to add those stems. Press again to stop.

**Endpoints** (all local, JSON): `POST /say {text}`, `POST /mute {muted}`, `POST /ptt {down}`, `POST /record/start {name?, mic?, music?}`, `POST /record/stop`, `GET /record/status`, `GET /usage` (per-turn counts), `GET /engine` (static model/capacity), `GET /memory` (read-only memory status: mode, backend, per-turn gates, recall attribution — names and counts only, never content). Each POST logs a `[control] …` line.

**Live token/context status block** — monospace lines below the input:
```
Tokens | <held> [<%> of <reliable> reliable] · <to line> · advertised <n> · model max
Engine | Inference Provider · Model ID
Agent  | Name: <character> · Voice: <voice>
Misc   | Session · Memory: full|recall-only|off (— = memory not configured) · net turn growth · total tok. xmitted
Memory | <backend> · per-turn: chat|chat + voice|off · recalled: <n> at open via <backend> · last turn: <n> extra(s) via <backend>
⚠ approaching reliable context line — …   ← appears only in the warn/over zone
```
The **`Memory`** line appears only when a memory seam is attached this sitting (the mode alone
always shows on `Misc`). It is a **read-only tap** (`GET /memory`, polled every 5 s): the active
backend (with a `(recall-only)` marker when nothing will be retained), the per-turn recall gates,
and the last recalls' **honest attribution** — each names the backend that *actually answered*, so
a floor fallback shows as `floor`, never masquerading as the primary. Names and counts only —
recalled text, your words, and the cue never ride this route. All memory *writes* (curation, mode
changes) live behind the facade's token door, not here.
`held` = the context the model holds *this turn* — the last request's prompt *plus its reply* (window occupancy, not cumulative). At open / resume / live switch it carries an **`est.` marker** (chars/4 seed over the pre-fill — system prompt, memory block, any restored transcript) until the first turn's server report replaces it. The gauge now measures against a **reliable-usable line** (`reliable` = the measured usable ceiling, `128,000` today), NOT the advertised window — so you see the *usable* wall coming. Watch **`to line`** (reliable budget remaining) tick down; the `Tokens` line **recolors and warns before the wall**:

| Zone | `held ÷ reliable` | Look |
|---|---|---|
| **ok** | `< 75%` | normal blue |
| **warn** | `75–100%` | amber + the `⚠ approaching reliable context line` banner |
| **over** | `≥ 100%` | red/bold + banner |

When you hit **warn**, wrap up or restart (a fresh session resets `held`). `advertised` (the context the server actually allocated) and `model max` are shown as references. If `reliable_context` isn't set for the model, the gauge falls back to gauging against `advertised`. The **`Agent`** line names the active persona — `character` + `voice`, resolved once from `config/active.toml` at startup (static; falls back to `—` if unresolved). `net turn growth` = how much the last turn added; `total tok. xmitted` = cumulative input this session. Capacity + Model ID come from an **engine probe** at startup, chosen by `LM_PROVIDER`: on the default `llama-server` it reads the server's native `GET /props` (allocated context from `default_generation_settings.n_ctx`; the GGUF filename as the model id — `llama-server` doesn't expose `--alias` there, and it reports no train-time maximum, so `model max` stays `—`). *If you use LM Studio* (`LM_PROVIDER=lmstudio`) it reads that app's native `/api/v0/models` instead, which supplies both the loaded and the maximum context. Either way, if the probe is unreachable the block shows `—` and the loop runs fine regardless.

> **Loopback only by default.** Binds to `127.0.0.1:65000`. To reach it from a phone on the LAN, launch with **`WEB_HOST=0.0.0.0`** set (e.g. `WEB_HOST=0.0.0.0 ./start.sh`) — that exposes text-inject/mute/PTT **plus the read-only status block (Model ID + aggregate token counts — no conversation content)** to every device on the network. **Owner opt-in**, not a default ("sensitive text stays local").

## Companion switcher (supervisor daemon)

With `[serve.supervisor]` enabled in `serve.toml` **and** the standalone facade up, the panel
grows a **COMPANION** box: pick character / voice / persona / model and press **Switch**. The
panel relays the click to the daemon's authed `POST /admin/switch`, which validates the
selection (registry + on-disk existence — a refused switch writes nothing), writes
`config/active.toml` (previous copy kept as `active.toml.prev`), and then applies it the
lightest way it can:

- **Live** — when every changed piece has a live path (persona · voice · model *field* among
  models your LLM server already holds; such models show a ● in the picker), the daemon hands
  the bundle to the running bot and it applies **at your next words**: the old session
  finalizes exactly as a graceful stop would (memory record, hold honored), the new
  companion's context seeds with its own recall, and the voice re-clones — no restart, the
  page stays up and shows *switched ✓*.
- **Warm restart** — anything heavier, a bot that is down, or a refused live arm falls back to
  the restart path: the bot warm-restarts (your LLM server is never touched), the page goes
  down with it and reloads itself when the new one is up (≈10–30 s).

Tick **keep this session** to drop a hold marker first, so the current session is kept as a
**named (held)** one (the `stop.sh --hold` semantics; sessions save by default either way, and
for a recall-only sitting the marker is what keeps the transcript) — honored on BOTH paths. The box hides
itself when the daemon isn't configured, isn't reachable, or the panel is LAN-exposed
(`WEB_HOST` not loopback — use the facade's authed `/admin/switch` directly there).

### The rest of the `/admin` surface

The supervisor subsystem ships **OFF** (`[serve.supervisor] enabled = false`). With it on, the
same bearer that guards the facade guards these routes, on the **facade port** (`:65001`), not the
panel. `/admin/switch` (above) is one of them; the rest round out the daemon face. Every response
carries names, states, and booleans only — never tokens, env values, or file contents.

| Route | Body | What it does |
|---|---|---|
| `GET /admin/launch` | — | The **standing launch page** (see below). The ONE unauthed route beside `/health` — a static shell with zero state; everything it shows arrives via authed fetch. |
| `GET /admin/state` | — | Bot state, panel reachability, each watched external's reachability (your LLM server, the speech server, plus any `[serve.supervisor.watch.<name>]`), and the last switch's outcome. |
| `GET /admin/sessions` | — (`?character=<name>` optional) | The saved-session shelf, **metadata only** (id, name, dates, turns, memory-mode stamp — never conversation content, never file paths). Feeds the launch page's resume picker. |
| `POST /admin/bot/start` | `{"mode":"new"}` or `{"mode":"resume","name":"<session>"}`; optional `"memory":"full\|recall-only\|off"` | Launch the voice bot. `memory` sets the sitting's posture (absent = full, or a resumed session's own stamp). Adopt-don't-collide: an already-running bot is adopted, not double-started (→ `409`). |
| `POST /admin/bot/stop` | `{"hold":true,"name":"<session>"}` (both optional) | Graceful **warm** stop — the bot's own finalize path runs; your LLM server is never touched. Sessions save by default; `hold` names the session (and keeps a recall-only transcript). |
| `POST /admin/daemon/restart` | — | Restart the facade process itself (the one restart it can't do in place); under a plain terminal run it simply exits for the keeper. |
| `GET /admin/roster` | — | The **roster wizard** page (the second static shell beside `/admin/launch` — contentless chrome, data by authed fetch). Onboard a new companion: persona + voice bundle + provenance + memory tier, preview-then-confirm, **create-only** (existing characters are never touched). Clips are conditioned to mono 24 kHz when `ffmpeg` is present; the new bundle is verified with the same loaders startup uses. Audition stays yours — your ear decides. |
| `GET /admin/roster/state` | — | Roster listing: names, voice tags, persona variants, memory backend map, active selection. Names only. |
| `POST /admin/roster/onboard` | multipart form; add `yes=true` to confirm | The wizard's verb — without `yes` it validates everything (clip conditioned in scratch, discarded) and answers a report; nothing persists. |
| `GET /admin/memory` | — | Per-companion memory-record counts + the backend each resolves to (names and numbers only). |
| `GET /admin/memory/records` | — (`?character=<name>` required) | One companion's canonical records: date, id, name, turn count, digest — the CLI `records` view; never the transcript. |
| `POST /admin/memory/forget` | `{"character":"<c>","session":"<id>"}`; add `"yes":true` to confirm | **Preview-then-confirm** forget of one session, same contract as the CLI: without `yes` it shows the digest and touches nothing; confirmed, it deletes the backend's facts FIRST, then the record (a failed index step keeps the record — re-runnable). Pre-keyed leftovers are reported with the `rebuild --clean` pointer; `rebuild` itself stays CLI-only (long extraction replay). |
| `GET /admin/actuators` | — | List declared actuators with note / running / last-run record (plus a reachability probe for any that declare one). No commands, no output. |
| `POST /admin/actuators/{name}/run` | — | Run one declared actuator, bounded by its timeout; the reply waits for the honest result. Same actuator already mid-run → `409`; unknown name → `404`. |

**Switch steering.** `POST /admin/switch` also takes an optional `"apply"` key — `"auto"` (default) ·
`"live"` (apply live or `409`, never restarts) · `"restart"` (force the warm-restart path). A second
switch while one is in flight is refused (`409`). An optional `"memory"` key sets the NEXT sitting's
posture — it forces the restart path (the mode is set at boot and never changes on a live handoff;
`"apply":"live"` + `"memory"` is refused).

### The launch page (`/admin/launch`)

The standing surface for starting and stopping the bot **without recalling any flags** — reachable
whether the bot is up or down, from any device that can reach the facade (it's plain HTTP, no
WebRTC). Open `http://<facade-host>:65001/admin/launch`; it asks for the serve bearer **once**
(kept in that browser's localStorage, sent only as an `Authorization` header) and then offers:

- **Start** (bot down): pick the companion (a different companion auto-fills a valid voice and
  rides `/admin/switch` with `start:true`), pick **— new session —** or a saved session off the
  shelf, pick the memory posture (default = full; a resumed session keeps its own saved mode).
- **Stop** (bot up): one button — the session saves by default; an optional *name this session*
  field is the "name it now" ergonomic. Plus a link into the proxied control panel.
- A live state line (bot / pid / uptime / externals / switch phase, polled every few seconds).

The page never bounces the facade itself — it starts and stops the **bot** only. First supervised
spawn on a fresh macOS install is a desk moment (the mic permission attributes to the daemon).
