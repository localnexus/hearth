# 2.5b The `/admin` surface

> Part of [2.5 Control panel & live status](../02.5-control-panel.md).

Every route Hearth's admin mount answers, with its body and its switch.

The launch page subsystem ships **OFF** (`[serve.supervisor] enabled = false`). With it on, the
same access key that guards Hearth guards these routes, on the **Hearth port** (`:65001`), not the
panel. `/admin/switch` (above) is one of them; the rest round out the launch page. Every response
carries names, states, and booleans only — never tokens, env values, or file contents.

| Route | Body | What it does |
|---|---|---|
| `GET /admin/launch` | — | The **standing launch page** (see below) — one of **six unauthed static shells** (with `/admin/first-run`, `/admin/roster`, `/admin/memory/ui`, `/admin/settings/ui`, `/admin/pair/ui` below). Zero state baked in; everything it shows arrives via authed fetch. **Ten paths skip the access key in total**: those six shells, `/health`, `POST /admin/pair/claim` — the one unauthed *verb*, which exists because a device without the key must be able to reach it (see the pairing rows below) — and the two brand images (`/ui/brand/favicon.png`, `/ui/brand/mark.png`), which are artwork only. |
| `GET /admin/state` | — | Companion state, panel reachability, each watched external's reachability (your model server, the speech server, plus any `[serve.supervisor.watch.<name>]`), and the last switch's outcome. Companion state is process truth, re-checked on every call: a companion started at the desk shows up (adopted) and one stopped at the desk drops off within one poll of the launch page — the state line is a live is-a-companion-running indicator either way. |
| `GET /admin/first-run` | — | The **first-run page** — the sixth unauthed static shell (contentless chrome, data by authed fetch). The guided first sitting behind the door `python -m hearth.init` opens: server → model id → Start → "heard you". Offered by the launch page while `/admin/state`'s `first_run` says `needs_model` or `fresh`; reachable at its address any time. |
| `GET /admin/first-run/state` | — | The two facts (`needs_model`: the selected model config still carries the shipped placeholder id; `fresh`: no companion here has a session yet), the selection, the model's name + id, the model URL Hearth uses with the ids it advertises right now (probed with Hearth's own LM token, which never leaves), and companion state. |
| `POST /admin/first-run/model` | `{"id":"<advertised id>"}`; add `"yes":true` to record an id the server does not list | Record the model id in the **selected** `model.toml` by the first-run setup's own surgery (comments kept, one `.prev` beside it; a file still resolving to the shipped tree is copied-on-write). An id the server does not advertise — or an unreachable server — answers `409` with the reason and the `advertised` list until told `yes`. The response states the effect time: the companion reads it at Start; Hearth's own `/v1` chat leg at its next restart. |
| `GET /admin/sessions` | — (`?character=<name>` optional) | The saved-session shelf, **metadata only** (id, name, dates, turns, memory-mode stamp — never conversation content, never file paths). Feeds the launch page's resume picker. |
| `POST /admin/bot/start` | `{"mode":"new"}` or `{"mode":"resume","name":"<session>"}`; optional `"memory":"full\|recall-only\|off"` | Launch the voice companion. `memory` sets the sitting's posture (absent = full, or a resumed session's own stamp). Adopt-don't-collide: an already-running companion is adopted, not double-started (→ `409`). |
| `POST /admin/bot/stop` | `{"hold":true,"name":"<session>"}` (both optional) | Graceful **warm** stop — the companion's own finalize path runs; your model server is never touched. Sessions save by default; `hold` names the session (and keeps a recall-only transcript). |
| `POST /admin/compact` | `{"character":"<c>","session":"<id>"}` | **Manual compaction initiation** (auto-compaction-on-close's desk knob — see [03.5-session-continuity.md](03.5-session-continuity.md)). Companion must be down. Clears any `.failed` breadcrumb and any dead claim for the pair, then fires immediately if the maintenance-lock stage is free, else queues for Hearth's compact watch. `409` only when an active compaction already owns the pair; otherwise `200` with a `note` saying whether it started now or queued. |
| `POST /admin/daemon/restart` | — | Restart the Hearth process itself (the one restart it can't do in place); under a plain terminal run it simply exits for the keeper. |
| `GET /admin/roster` | — | The **roster wizard** page — another unauthed static shell (contentless chrome, data by authed fetch). Onboard a new companion: persona + voice bundle + provenance + memory tier, preview-then-confirm, **create-only** (existing characters are never touched). Clips are conditioned to mono 24 kHz when `ffmpeg` is present; the new bundle is verified with the same loaders startup uses. Audition stays yours — your ear decides. |
| `GET /admin/roster/state` | — | Roster listing: names, voice tags, persona variants, memory backend map, active selection. Names only. |
| `POST /admin/roster/onboard` | multipart form; add `yes=true` to confirm | The wizard's verb — without `yes` it validates everything (clip conditioned in scratch, discarded) and answers a report; nothing persists. |
| `GET /admin/roster/persona` | `?character=<c>` (+ `&persona=<variant>`) | The persona text for the editor (authed — persona content crosses only behind the door). Says whether it resolves to the data folder or the shipped tree. |
| `POST /admin/roster/persona` | `{"character":"<c>","persona":"<v>?","text":"…"}`; add `"yes":true` to write | **Preview-then-confirm** persona write. Always lands in the DATA overlay (a shipped persona is copied-on-write, never edited in place); an overwrite keeps one `.prev` backup; the write is verified with `compose_persona` and rolled back if composition breaks. Effect at companion start / live switch. |
| `POST /admin/roster/voice` | multipart form; add `yes=true` to confirm | **Add a voice to an existing character** — the wizard's clip pipeline, create-only per TAG (existing bundles are never overwritten), bundle written under DATA (works for shipped characters), provenance appended to the character's `VOICE-SOURCE.md`. The new tag is in the switch pickers immediately. |
| `POST /admin/roster/fork` | `{"character":"<c>","as":"<name>","until":"<when>"}` (+ `"include_sessions":true`); add `"yes":true` to confirm | **Branch a character's memory track at a juncture** — the web skin over `python -m hearth.memory fork` (docs/memory.md, "Forking the track at a juncture"): same plan/execute pair, same validation and rollback, create-only. Without `yes` it answers the full plan (records that copy, what stays behind, tier) and writes nothing. One divergence, deliberate: the backend **replay stays at the desk** — a non-floor fork answers "created" plus the exact `rebuild` command (extraction over every record runs minutes, unbounded by request timeouts, the same reason `rebuild --clean` is CLI-only). The roster page's Branch card wraps this with a record picker: click the last shared session and its full-precision `ended` becomes the juncture. |
| `GET /admin/memory` | — | Per-companion memory-record counts + the backend each resolves to (names and numbers only). |
| `GET /admin/memory/records` | — (`?character=<name>` required) | One companion's canonical records: date, id, name, turn count, digest — the CLI `records` view; never the transcript. |
| `POST /admin/memory/forget` | `{"character":"<c>","session":"<id>"}`; add `"yes":true` to confirm | **Preview-then-confirm** forget of one session, same contract as the CLI: without `yes` it shows the digest and touches nothing; confirmed, it deletes the backend's facts FIRST, then the record (a failed index step keeps the record — re-runnable). Pre-keyed leftovers are reported with the `rebuild --clean` pointer; `rebuild` itself stays CLI-only (long extraction replay). |
| `GET /admin/memory/facts` | — (`?character=<name>` required) | The bank's indexed-fact count — one deliberate backend call (the pane hits it on selection, never on a poll). Honest `null` when the memory lane is down, the companion maps `"none"`, or the backend keeps no separate index (the floor); counts past one page answer `capped: true`. |
| `GET /admin/memory/ui` | — | The **review-and-prune pane** — another unauthed static shell: companions with record counts → per-companion record digests + the lazy fact count → per-record preview-then-confirm forget, all via the authed routes above. |
| `GET /admin/settings` | — | The settings overview: every registry-declared config-file kind with its discovered files and their strict-check verdicts (the same validation as `python -m hearth.config.check`; errors name keys, never values). |
| `GET /admin/settings/schema` | — | The settings registry's JSON Schema bundle — the contract the generated forms render from (types, ranges, defaults, live-path/effect-time `x-hearth` stamps). |
| `GET /admin/settings/file` | — (`?file=<label>` from the overview) | One file's parsed values. Secret-marked fields (the hindsight API key, the env maps) arrive REDACTED — their values never leave the file, even behind the door. |
| `POST /admin/settings/set` | `{"file":"<label>","key":"<dotted>","value":…}`; add `"yes":true` to confirm | **Preview-then-confirm** write of ONE scalar key: validated against the declared schema, applied by comment-preserving line surgery, parse-verified before the atomic replace (a surgery that would touch anything else is refused — edit by hand). A shipped file copies-on-write into the data folder; an overwrite keeps one `.prev` backup. The response states the honest effect time (live path, or what must restart). `active` points at `/admin/switch`; the panel-managed layers point at the :65000 panel; secrets and structured values refuse. |
| `GET /admin/settings/ui` | — | The **generated settings forms** — the fourth unauthed static shell: every knob rendered from the served schema — control by type, current value vs default, live/effect-time badge, verdict per file — with the preview-then-confirm write flow above. A knob cannot exist without appearing here. |
| `GET /admin/actuators` | — | List declared actuators with note / running / last-run record (plus a reachability probe for any that declare one). No commands, no output. |
| `POST /admin/cookie` | — | Mint the **browser carrier**: a cookie that stands in for the access key on a plain navigation, which cannot attach a header. The value is DERIVED from the access key (HMAC), never the access key itself, so the raw secret never enters a cookie jar and the cookie cannot be replayed as an `Authorization` header. `HttpOnly` (no page script reads it back), `SameSite=Lax`, 30 days, no `Secure` — Hearth speaks plain HTTP, and the overlay network is what encrypts the hop. Rotating the access key invalidates every carrier; there is no server-side session state. This is what makes the proxied `:65000` panel reachable from a browser. |
| `POST /admin/actuators/{name}/run` | `?force=1` (optional) | Run one declared actuator, bounded by its timeout; the reply waits for the honest result. Same actuator already mid-run → `409`; unknown name → `404`. One declared with `guard = "companion"` answers `409` with `guard` named while a companion is running (process truth, reconciled first); `?force=1` is the confirmed press that runs it anyway. |
| `POST /admin/pair` | — | **Mint a six-digit pairing code** (authed — this is the desk end). A 64-hex access key is not something anyone types into a phone, so the desk opens a short window instead of moving the key by hand. Exactly **one** code exists at a time; minting again replaces it. Answers the code and its expiry. |
| `POST /admin/pair/claim` | `{"code":"<six digits>"}` | Trade the code for the access key, **once**. Unauthed by necessity — this is precisely what a device *without* the key can reach — so the safety is the shape of the window: one live code, **5 minutes**, **burned on first use**, and **burned after three wrong guesses**. Every failure answers identically, revealing nothing about which part was wrong. |
| `GET /admin/pair/ui` | — | The **pairing page** — the fifth unauthed static shell. Pure chrome: it carries no token and no state, takes the six digits, stores the access key in that browser, mints the carrier cookie, and redirects to the launch page. |
| `GET /ui/brand/favicon.png` | — | The tab icon every page references. Unauthed because a `<link rel="icon">` on a navigation cannot carry the access key — the same constraint that made the switch card a splice. Served once and cached for a day rather than inlined as base64 into six pages. Also served by the `:65000` panel, from the same file. |
| `GET /ui/brand/mark.png` | — | The Hearth mark in every page header, same terms. **Artwork only:** these two rows are not a general static route, and nothing that reads operator state may ever join them. |

**Switch steering.** `POST /admin/switch` also takes an optional `"apply"` key — `"auto"` (default) ·
`"live"` (apply live or `409`, never restarts) · `"restart"` (force the warm-restart path). A second
switch while one is in flight is refused (`409`). An optional `"memory"` key sets the NEXT sitting's
posture — it forces the restart path (the mode is set at boot and never changes on a live handoff;
`"apply":"live"` + `"memory"` is refused). When the restart path fires (warm restart, or a fresh
spawn via `"start":true` on a down companion), the body's session-continuity keys ride along too —
`"mode":"new"|"resume"`, `"name":"<session>"` (the one to resume), `"hold":true` + optional
`"hold_name":"<name>"` (drop a hold marker on the OUTGOING session before it stops, same as
`stop.sh --hold`) — this is what the launch page's companion picker and "keep this session" tick
actually send.
