# 3.5 Session continuity (Tier 1) — resume a conversation across a restart

*What this covers: the conversation transcript that survives stops and crashes — where it lives, the saved-by-default rule, and the resume/name/discard CLI.* · Runbook index: [`README.md`](README.md)

The conversation transcript survives stops, an earbud-battery death, a crash, a reboot, an LM-server restart.

- **Where it lives / what it is:** `characters/<character>/sessions/<id>.json` (under the data folder) — a **full plaintext
  transcript** of one conversation (the model message list; the persona prompt is NOT stored).
  Local-only, **gitignored**, dir `0700` / files `0600`. Rewritten after every turn (atomic).
- **Saved by default:** a graceful `./stop.sh` **keeps** the file (an unclean death keeps it too) —
  a conversation never vanishes because a flag wasn't passed. Deleting is the explicit act
  (`--discard-held`, or remove the file). The one carve-out: a `--memory recall-only` sitting
  stays **transcript-ephemeral** — deleted on graceful stop, its crash leftover swept by the next
  fresh start — unless explicitly held.
- **Resume:** `./start.sh --resume` (picks if >1, metadata only) · `./start.sh --resume <file|name>`.
  The companion stays silent until spoken to, then answers with the reloaded memory (no auto-greeting).
- **Bare `./start.sh` → chooser (interactive terminal, only when ≥1 resumable session exists):**
  a metadata-only menu — `0. new session` + every saved session by name/timestamp (named ones
  tagged `[HELD]`); Enter/Ctrl-C cancels. On a fresh install / empty shelf it starts fresh with
  no menu — nothing to choose from.
  **Non-interactive** (launchd / web, stdin not a TTY) starts fresh without discarding anything;
  the hard **guard** (`exit 2`) now fires only when a recall-only leftover is present, so
  automation never silently deletes the privacy tier's one recovery chance.
- **Memory posture for one sitting:** `./start.sh --memory recall-only|off` governs the memory
  **bank** (recall/retention — see [memory.md](../memory.md) → "Per-session memory mode"). One
  transcript rule keys off it: a recall-only sitting's transcript is deleted on graceful stop
  unless held (the rest of this page is mode-independent). Non-full sittings stamp the session
  file, and `--resume` without the flag inherits the stamp — a crashed recall-only sitting stays
  unretained.
- **Name one:** `./stop.sh --hold [name]` marks the session **held** — sticky, sweep-exempt,
  named for `--resume <name>` (sessions save either way; held is the *named, never-sweep* class,
  and the explicit keep for a recall-only transcript). Remove held: `./stop.sh --discard-held <name>`
(targeted) — a bare/`--all` wipe of **all** held sessions is irreversible and requires typing **`HEARTH`** to confirm (refused non-interactively).

Never expose `sessions/` over the web `/` or sync it. See [debugging/session-continuity-faults.md](../debugging/session-continuity-faults.md).

## Auto-compaction on close (safety net)

A HELD session that closes gracefully past ~40K tokens (the server's own last
prompt count, or file-size/4 — whichever is larger) drops a request in
`DATA/ops/compact-queue/`; Hearth's **compact watch**
(`[serve.supervisor].compact_watch`, on by default) runs the operator's
compactor (`DATA/ops/compaction/compact-companion-session.sh`, if installed) once no companion
is alive. In-progress truth is the **per-character maintenance lock** — a
kernel flock under `DATA/locks/session-maintenance/`, held by a live companion for <!-- manual-lint: allow: GPU/OS kernel, the technical sense -->
the session's life and by a compaction for the run's life, released by the
kernel on any death (no stale state). While a compaction holds it, companion starts <!-- manual-lint: allow: GPU/OS kernel, the technical sense -->
refuse with the holder's info (the launch page shows "compacting … since …"
and simply works once free). A failed run leaves a `.failed` breadcrumb and
is **never retried automatically** — inspect `DATA/logs/compact-auto.log`,
then delete the `.failed` file to re-arm. Unclean companion deaths skip the trigger
by design (outage-resume path).

**RAM floor:** when the compaction model must be *loaded*, the compactor
requires headroom (default 200 GB available; a resident model skips the
switch). A watch-claimed run that falls short **defers** — the request is
re-parked with a timestamp and retried about every ten minutes — while a
manual run halts and says why (`--ram-floor-gb` overrides; 0 disables).

**Manual initiation:** the launch page's **"Compact selected session"**
button (companion down; pick the companion + session — sizes shown as `~Nk tok`)
posts `/admin/compact`, which clears any `.failed` breadcrumb for the pair
and fires immediately when the stage is free, else queues for the watch. The
status line shows "compacting … since …" while it runs.
