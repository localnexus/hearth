# The LLM (model, persona, tone, backend)

**Change the model** → set `model =` in **`config/active.toml`** (names a dir under `config/models/<model>/`; that dir's `model.toml` `id` is the LM Studio model id, verbatim). **Edit + restart** — nothing is hot-swapped. *(`config_loader.load_active()` resolves it at startup and fails fast, naming the file, if it's missing/malformed.)*
```bash
# list ids in LM Studio (use the id VERBATIM — prefixes are inconsistent):
curl -s http://127.0.0.1:1234/v1/models -H "Authorization: Bearer $(cat ~/.lmstudio/lm-probe-token)" \
  | python3 -c 'import sys,json;[print(m["id"]) for m in json.load(sys.stdin)["data"]]'
```
**Default:** a ~35B-parameter, 3B-active MoE instruction model (depth + speed, served by LM Studio on `:1234`), run as a hybrid-thinking model with thinking forced off — see the rules below. Some large hybrid-attention models keep no reusable per-token KV, so cross-turn caching can't work and TTFB climbs sharply at depth; a model that supports prefill caching is preferred for interactive use. A stock (non-re-quant) build of the same model makes a good fallback baseline.

⚠️ **Two hard rules:** (1) the model must be **loaded** in LM Studio; (2) it must emit **no chain-of-thought** — either a pure instruct / natively-non-thinking model, **or** a *hybrid* (Qwen3.6, GLM, …) with thinking forced off. A model that streams `reasoning_content`/`<think>` and leaves `content` empty stalls the loop. A hybrid-thinking default **requires** thinking forced off. To **disable hybrid thinking** in general use `reasoning_effort = "none"` (set in the active `model.toml`, fed into the LLM `Settings` `extra` at startup) — on this LM Studio build it is the ONLY body field that works (`chat_template_kwargs` / `enable_thinking` are silently ignored). ⚠️ Some third-party **uncensored re-quants** ignore even that — they need the persistent LM Studio **Prompt-Template** edit (`{%- set enable_thinking = false %}`). A natively non-thinking model needs none of this. Sanity-check it streams non-empty `content`:
```bash
curl -s -N http://127.0.0.1:1234/v1/chat/completions -H "Authorization: Bearer $(cat ~/.lmstudio/lm-probe-token)" \
  -H 'Content-Type: application/json' -d '{"model":"<id>","messages":[{"role":"user","content":"hi"}],"max_tokens":20,"stream":true}' \
  | grep -o '"content":"[^"]*"' | head
```

**Persona / behavior** → edit **`characters/<character>/persona.md`** (the CHARACTER layer — `## IDENTITY` + `## SOUL`) and/or the active model's **`config/models/<model>/system-prompt-template.md`** (the MODEL layer — output-shaping hard rules + model-whispering, with a `{{persona}}` slot). At startup `config_loader` composes them into `system_instruction` (template with `{{persona}}` filled by IDENTITY-body + `\n\n` + SOUL-body). Keep the "short, spoken, no markdown" hard rules — they live in the template — or replies read badly aloud. ⚠️ Any non-byte-equivalent edit changes the prompt's `sha256` and warns on resume of pre-edit sessions (by design). **Restart** to apply.
**Voiced-breath cues (model-layer capability)** → the template's hard rules instruct the model to emit a whitelist of **nine paralinguistic cue tags** — `[laugh] [chuckle] [sigh] [gasp] [groan] [sniff] [cough] [shush] [clear throat]` — which **Chatterbox-Turbo consumes as breath/sound events, never spoken aloud**. The no-stage-directions rule carries a carve-out for exactly these nine; the prompt also states the placement law (set a cue off with punctuation, keep the turn short — never bury it mid-phrase) and a restraint-first framing. This is a **prompt capability, not a code knob** — it lives in `config/models/<model>/system-prompt-template.md` (a non-byte-equivalent change, so it warns on resume of pre-edit sessions). A deterministic **TTS-side repair layer backstops it** — `paralinguistics.normalize()` in `mlx_tts_service.run_tts` rewrites a fumbled-wrapper / wrong-case / morphed cue (`*sigh*`, `[SIGHS]`) to the canonical `[tag]` and strips un-performable `[gentle smile]`/`[gentle pause]` beats before synthesis (see [voice & TTS](voice-tts.md)). **Restart** to apply.
**Creativity** → `temperature` in the active **`config/models/<model>/model.toml`** (~0.7 now). Add `top_p`/`max_tokens`/etc. inside `OpenAILLMService.Settings(...)` in `bot.py`.
**Context-budget gauge line** → `reliable_context` in the active **`config/models/<model>/model.toml`** (`128000` today). The control panel's `Tokens` line gauges held-tokens against this **measured usable ceiling**, not the advertised `loaded_context_length` (262,144) — with ok (`<75%`) / warn (`75–100%`) / over (`≥100%`) zones and a pre-emptive "approaching reliable context line" banner. It's a **PROVISIONAL cost/prudence cap**, NOT a measured recall cliff (a needle sweep found none to ~207k). Rides `/engine` as `engine_info["reliable"]`; if omitted the panel falls back to gauging against the advertised window.
**Different backend / token** → `LMSTUDIO_BASE_URL` (`bot ~L104`) for any OpenAI-compatible server; token via env `LM_API_TOKEN`. Keep it local ("sensitive text stays local"). *(A headless `mlx_lm.server` in place of LM Studio is an operational choice, not a speed one; the LLM isn't the bottleneck.)*
